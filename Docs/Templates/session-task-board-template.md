# 문서 제목

> 채팅 세션 단위 작업 보드 템플릿

## 1. 목적
- 이번 채팅 세션에서 끝낼 단일 결과물 1개를 추적한다.
- 채팅 내용과 별개로 현재 작업, 다음 작업, 남은 이슈를 짧게 유지한다.

## 2. 운영 규칙
- `Now`에는 현재 진행 중인 작업 1개만 둔다.
- 작업 항목은 추상 명사가 아니라 행동 단위로 적는다.
- 새로 발견한 일은 즉시 처리하지 말고 `Inbox` 또는 `Parking Lot`에 먼저 기록한다.
- 현재 목표를 직접 막는 항목만 `Now` 또는 `Next`로 승격한다.
- 세션 종료 시 `Inbox`를 정리하고 `Done`, `남은 리스크`, `다음 시작점`만 남긴다.

## 3. 비 필수 항목 규칙
- 모든 섹션이 항상 채워져야 하는 것은 아니다.
- `Blocked`, `Inbox`, `Parking Lot`, `Notes` 등 비 필수 섹션은 해당 사항이 없으면 비워두거나 섹션 자체를 생략할 수 있다.
- 명시적 근거가 없는 항목은 새로 만들어 채우지 않는다.
- 대화에서 논의되지 않았고, 코드/문서/검증에서 확인되지 않은 할 일이나 이슈를 추정으로 기록하지 않는다.
- `Parking Lot`은 이번 세션 중 실제로 발견되었지만 현재 범위에서 제외하기로 한 항목만 기록한다.
- `Blocked`는 실제 진행 차단 조건이 확인된 경우에만 기록한다.
- `Inbox`는 세션 중 새로 발견된 메모만 기록한다.
- 내용이 없으면 `없음`으로 짧게 표시하거나 공란으로 둔다.

## 4. 권장 템플릿

```md
# SESSION-YYYYMMDD-NN

## Session Goal
- 한 줄 목표:
- 완료 기준:
- 이번 세션에서 하지 않을 것:

## Now
- [ ] T1. 작업명
  - 목적:
  - 완료 기준:
  - 검증:
  - 근거:

## Next
- [ ] T2. 다음 작업
  - 완료 기준:
  - 검증:
  - 근거:
- [ ] T3. 다음 작업
  - 완료 기준:
  - 검증:
  - 근거:

## Blocked
- [ ] B1. 막힌 작업
  - 막힌 이유:
  - 필요한 결정/정보:
  - 임시 우회 가능 여부:
  - 근거:

## Inbox
- [ ] I1. 방금 발견한 이슈
  - 근거:
- [ ] I2. 확인 필요 메모
  - 근거:

## Parking Lot
- [ ] P1. 이번 목표와 직접 관련 없는 개선
  - 근거:
- [ ] P2. 다음 세션 후보 작업
  - 근거:

## Done
- [x] D1. 완료한 작업
  - 검증 결과:
- [x] D2. 완료한 작업
  - 검증 결과:

## End of Session
- 결과:
- 남은 리스크:
- 다음 세션 시작점:
```

## 5. 작성 예시
- 나쁜 예: `디스폰 정리`
- 좋은 예: `Request 단계에서 Disable 요청 생성 경로를 하나로 통합`
- 나쁜 예: `테스트`
- 좋은 예: `PlayMode 스모크 씬에서 1만 발 제거 시 기동/루프 정상성 확인`
