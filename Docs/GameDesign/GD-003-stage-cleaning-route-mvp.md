> 적용 범위: 스테이지 공통 규칙 중 **동선/스폰 분포(체감)** 파트
> 본 문서는 다음 2개 방안을 **우선 적용**한다.
> 1) "청소 흔적" 기반 스폰 분포(자리 이동 유도)
> 2) Source 경계 → Deposit까지 이동 시간 3~6초 내외(빠른 템포 유지)

---

## 0. 목표
1. **자리 고정(제자리 파밍) 제거**
   - 같은 좌표에 머무르는 플레이가 자연스럽게 비효율이 되도록 한다.
2. **빠른 플레이 템포 유지**
   - Deposit이 필수 행동(Load 비우기)임에도 왕복이 다운타임으로 느껴지지 않게 한다.
3. **Source 고갈 기반 진행과 합치**
   - "여긴 다 치웠다" 체감(고갈/약화/고갈 완료)이 동선 변화로 연결되게 한다.

### 경험 의도

본 문서의 자리 이동 유도는 단순히 이동량을 늘리기 위한 장치가 아니다.
핵심은 플레이어가 Source 내부의 여러 지점을 직접 청소하면서,
Hazard 압력 속에서도 구역을 자기 손으로 정리하고 정복해 나간다는 감각을 만드는 데 있다.

따라서 Source 공략은 경계 바깥과 Deposit 사이를 안전하게 왕복하는 수거 루틴이 아니라,
Source 내부에서 다음 청소 지점을 선택하며 조금씩 전장을 탈환하는 과정으로 읽혀야 한다.

이 문서에서 경계하는 해석은 다음과 같다.
- Source 바깥과 Deposit 왕복만으로 루프가 닫히는 것
- 내부 청소보다 외곽 효율 루프가 더 우세해지는 것
- 구역 정리의 진행 감각 없이 반복 수거처럼 체감되는 것

---

## 1. 최소 루프(동선 관점)
### 1.1 루프 정의
- Source 영역 진입 → 수거(청소)로 Load 증가 + Source 진행(남은 청소 필요량 감소)
- Capacity 도달 시 Trash 수거 불가 + Hazard 조건부 제거만 가능 → Deposit으로 이동하여 Load 비움
- 재진입하여 남은 구역을 계속 청소, Source를 Weakened/Depleted로 전환

### 1.2 동선이 유도해야 하는 선택
- "지금 자리에서 더 머물지"가 아니라
  **"Source 영역 내부에서 다음 청소 좌표로 이동"**이 기본 선택이 되도록 한다.

---

## 2. Deposit 거리 설계 (Source 경계 → 3~6초)
### 2.1 설계 원칙
- Deposit은 **스테이지 내 안정적으로 존재**한다.
- Source 경계(영역 밖으로 나오기 직후)에서 Deposit까지의 이동 시간은
  - 목표: **3~6초**
  - 초과 시 다운타임 인식 가능성이 커지므로, 초과하는 경우 경로/장애물/회피 요소를 "짧고 의미있는 플레이"로 보정한다.

### 2.2 배치 권장 형태
- 기본 구조: **Deposit 허브 + Source 스포크**
  - Deposit을 스테이지의 허브 성격으로 두고,
  - 여러 Source로 뻗는 구조를 사용하면 왕복 비용이 일정해져 루프 템포가 안정된다.
- Source별 접근성 편차는 과도하게 두지 않는다(특정 Source만 유리/불리해지는 문제 방지).

### 2.3 거리 설계의 기대 효과
- Deposit이 "가까운 버튼"이 아니라 **짧은 왕복 동선**으로 작동한다.
- Load가 차면 반드시 이동하게 되어, 플레이가 자연스럽게 "구역 단위 청소"로 흐른다.

---

## 3. "청소 흔적" 기반 스폰 분포 (자리 이동 유도)
### 3.1 핵심 개념
Source 영역 내부에 "청소 흔적"을 남겨,
- 방금 청소한 자리 주변은 한동안 비어 보이고
- 아직 청소하지 않은 자리에서 스폰이 더 잘 일어나도록 만든다.

이를 통해 **Source 영역 내부에서 지속적으로 좌표 이동**이 발생한다.
이 이동 유도의 목적은 단순한 동선 분산이 아니라, `구역을 정리해 나가는 정복 감각`을 만드는 데 있다.

### 3.2 모델(개념 정의)
Source 영역을 셀/섹터 단위로 분할하고, 각 단위는 "오염도(스폰 가중치)"를 가진다.

- `CellPollution` (또는 `SpawnWeight`)
  - 높을수록: 쓰레기 스폰이 잘 됨(더러운 자리)
  - 낮을수록: 스폰이 잘 안 됨(방금 청소한 자리)

### 3.3 오염도 변화 규칙(요약)
- **청소(수거/제거) 성공 시**:
  - 해당 위치(또는 영향 반경)의 `CellPollution`이 감소한다.
- **시간 경과 시**:
  - `CellPollution`이 천천히 회복한다.
  - (본 문서 v1에서는 "이탈 가속 회복" 등 추가 장치는 적용하지 않는다.)

### 3.4 스폰 규칙(요약)
- 쓰레기 스폰은 Source 반경 내에서 발생하되,
  - `CellPollution`이 높은 셀을 우선적으로 선택한다.
- 결과적으로 플레이어는:
  - 한 자리를 청소하면 그 자리는 당분간 비고,
  - "다음으로 더러운 자리"로 이동하는 게 더 효율적이 된다.

### 3.5 동선 체감 목표
- 플레이어가 한 지점에서 **2~5초 이상 고정**하면
  - 주변 밀도가 눈에 띄게 떨어져서
  - 자연스럽게 "옆으로 옮겨야겠다"가 발생해야 한다.
- 이때 이동은 Source 내부 "다음 좌표"로의 이동이지,
  - Source 경계 왕복(핑퐁)이 기본 해법이 되면 안 된다.

### 3.6 MVP 구현 결정 (2026-02-19)
- 구현의 핵심 의도는 아래 3가지로 고정한다.
  - 오염도 변화는 플레이어가 체감 가능한 단일 규칙으로 유지한다.
  - 스폰 분포는 "방금 청소한 자리보다 다음 더러운 자리"를 우선적으로 보여준다.
  - 원형 Source에서도 "경계 밖에서 뜬금없이 나오는 느낌"이 최소화되어야 한다.
- 기술 계약(요청 누적/소비, 샘플링 방식, valid 셀 처리)은 [TD-003](../TechnicalDesign/TD-003-spawn-directive-model.md)에서 관리한다.

### 3.7 GD-014와의 관계
- 본 문서는 청소 흔적 도입의 MVP 기준과 최소 동선 목표를 다룬다.
- 복구를 단순 시간 회복이 아니라 공간 순환 규칙으로 확장하는 방향과 판독 기준은 [GD-014-cleaning-trace-recovery-loop.md](./GD-014-cleaning-trace-recovery-loop.md)에서 관리한다.
- 구현 우선순위는 여전히 본 문서의 MVP 기준이 먼저이며, `GD-014`는 후속 고도화 기준으로 본다.

## 4. 동선 시나리오(의도된 플레이 흐름)
1) Source 외곽 진입
2) 가까운 고오염 셀에서 수거가 잘 되고 Load가 상승
3) 동일 좌표에서 수거가 진행되면 주변 `CellPollution`이 감소 → 밀도 하락 체감
4) 플레이어는 Source 내부의 다른 고오염 구역으로 이동
5) Load가 Capacity에 접근하면 Trash 수거는 멈추고, Hazard는 조건부 성공 시 제거만 가능(진행도 미반영)
6) Source 경계 밖으로 이탈 → 3~6초 이동 → Deposit에서 Load 비움
7) 다시 Source로 진입하여 남은 고오염 구역을 청소
8) Source가 Weakened/Depleted로 진행되며 "여긴 다 치웠다"가 성립 → 다음 Source로 이동

---

## 5. 튜닝 레버(밸런싱 파라미터)
### 5.1 공간 단위
- `CellSize`: 셀 크기(체감상 "한 자리"의 크기)
- `CleanRadius`: 청소 시 영향을 받는 반경(0이면 단일 셀)

### 5.2 오염도 변화
- `PollutionDropPerCollect`: 수거 1회(또는 제거 1회)당 오염도 감소량
- `PollutionRegenRate`: 초당 오염도 회복량
- `PollutionMin/Max`: 오염도 하한/상한(스폰 완전 차단 여부 포함)

### 5.3 스폰 선택
- `WeightedSamplingMode`:
  - 전체 룰렛 방식(전체 셀 가중치 기반)
  - 상위 K 셀 중 선택(고오염 우선 강화)
- `SpawnTryPerTick` / `SpawnBudget`: 스폰 시도량(성능 가드 포함)

### 5.4 Deposit 동선
- `DepositTravelTimeTarget`: 3~6초 목표
- Source별 Deposit 접근성 편차 허용 범위(권장: 크지 않게)

## 6. 검증 체크리스트 (플레이테스트 관찰 포인트)
1) 플레이어가 Source 내부에서 실제로 **좌표를 옮기나?**
   - 같은 자리에 오래 서 있으면 밀도 하락이 체감되는가?
2) Deposit 왕복이 **다운타임**으로 느껴지지 않나?
   - 3~6초 목표가 적절한가?
3) Capacity에 도달했을 때 루프가 **끊기지 않고** 자연스럽게 Deposit으로 이어지나?
4) "경계 왕복(핑퐁)"이 최적이 되지 않나?
   - 핑퐁이 강하면: 오염도 하락/회복 속도, 셀 크기, 스폰 샘플링 방식을 조정한다.

## 7. 후속 확장(본 문서 범위 밖)
본 방안을 적용해도 경계 핑퐁/다운타임 문제가 남는 경우,
다음 후보를 **추가 장치**로 검토한다.

- 이탈 중 오염 회복 가속(거리 설계의 다운타임 완화)
- Remaining(청소 필요량) 롤백 기반 억제(탄력 회복/2층 예산 등)
- 경계 그라데이션(외곽 수익 감소) 강화
- 진입/탈출 동선 분리(토폴로지로 핑퐁 억제)
