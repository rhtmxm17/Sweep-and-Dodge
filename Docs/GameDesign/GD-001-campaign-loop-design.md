# 선형 캠페인 게임 루프 기획 정리

본 문서는 "단일 스테이지 내 플레이(수거/Deposit/위험탄/Source 고갈)"를
**15~20분 분량의 선형 캠페인**으로 구성하기 위한 상위 게임 루프 정의다.
튜토리얼(학습 단계 구성)은 별도 문서로 분리한다.

---

## 0. 목표 / 스코프

- 목표 분량: **실패(스테이지 재시도) 없이 연속 클리어 시 15~20분**
- 시간 기준: `OPS-001`의 페이싱 기준(스테이지 2~3분, 캠페인 15~20분)을 따른다.
- 진행 방식: **선형 캠페인(스테이지 1 → 2 → … → 엔딩)**
- 캠페인 내 메타 성장/영구 강화는 이번 문서 범위 밖(필요 시 별도 문서)

---

## 1. 용어 정의

- **Source**: 탄(Trash/Hazard)의 발생원. 단계(Phase)와 스폰 프로파일을 가진다.
- **Phase**: Source 진행 단계. 단조 증가만 허용.
  - `Normal` → `Weakened` → `Depleted`
- **CarryBin.Load**: 플레이어가 현재 들고 있는 수거량(스테이지 진행에 직접 영향).
- **CarryBin.Capacity**: 수거 가능한 최대 적치량.
- **Deposit**: CarryBin.Load를 비워 추가 수거가 가능하게 만드는 장치/지점.
- **Hazard(위험탄)**: 피격을 유발하며, 별도의 조건부 제거 규칙을 가진 탄.
- **Hit(피격)**: Hazard 충돌로 발생하는 패널티 이벤트.

## 2. 스테이지 규칙 (공통)

### 2.1 클리어 조건
- **스테이지 목표: 모든 Source가 `Depleted` 상태에 도달**
- (선택) 잔탄 처리까지 요구할지 여부:
  - 옵션 A: "Source만 Depleted면 클리어"
  - 옵션 B: "Source Depleted + 활성 탄 0이면 클리어"
- 캠페인 초기(1~2스테이지)는 옵션 A 권장(완주 템포 우선)

### 2.2 Source 진행(단조 증가, 롤백 금지)
- Source는 단계별 "남은 청소 필요량(예산)"을 가진다.
  - `Remaining_Normal`
  - `Remaining_Weakened`
- 현재 단계 예산이 0이 되면 다음 단계로 전환한다.
- `Depleted`는 최종 상태이며 **어떤 이유로도 이전 단계로 되돌아가지 않는다.**
- 단, 단조 증가 및 롤백 금지는 '단계' 자체에 대한 지침이다.
  - 남은 청소 필요량은 하기 피격 패널티 등의 요인으로 초기값 이상이 될 수 있다.

### 2.3 CarryBin / 수거 제한
- 수거/캡처 성공 시 CarryBin.Load가 증가한다.
- **Capacity 도달 시 Trash 수거가 멈춰야 Deposit이 필수 행동이 된다.**
  - `Load == Capacity`이면:
    - Trash는 Vacuum/캡처로 수거할 수 없다(= Load 증가 없음).
    - Hazard는 조건부 성공 시 `수거` 대신 `제거`로 처리할 수 있다.
    - `HazardRemovedWhenCarryFull`는 디스폰만 수행하며 CarryBin/Source 진행/HazardStack/`Collect` 집계에는 반영하지 않는다.
    - 플레이어는 Deposit으로 돌아가 Load를 비운 뒤 다시 수거해야 한다.

### 2.4 Deposit 동작(MVP)
- Deposit은 스테이지 내 반복 행동을 위한 "비우기" 기능만 담당한다.
- 기본 규칙:
  - Deposit 수행 시 `CarryBin.Load = 0`
- 트리거 방식(결정 필요, MVP는 하나로 고정):
  - 옵션 A: 접촉 즉시 비우기(템포 우선)
  - 옵션 B: 접촉 + 인터랙션(의도성 우선)
- Deposit은 "안전지대" 연출의 기준점이 될 수 있으나, 무적/치유 같은 추가 효과는 별도 결정.

### 2.5 Hazard(위험탄) 규칙(공통 개념)
- Hazard는 기본 수거로 즉시 처리되지 않으며, 별도의 조건부 제거 룰을 가진다.
- Hazard 조건부 성공 결과는 2가지로 고정한다.
  - `HazardCaptured`:
    - 조건: `Load < Capacity`
    - 처리: 수거 + 보상 적용(Carry/Source 진행/HazardStack/`Collect` 반영)
  - `HazardRemovedWhenCarryFull`:
    - 조건: `Load == Capacity`
    - 처리: 제거 전용(디스폰 + 전용 피드백), Carry/Source 진행/HazardStack/`Collect` 미반영
- 피격 처리:
  - 피격 시 iFrame/VacuumLock 등 제약이 발생(상세 수치는 밸런싱 문서 범위)

## 3. 피격 패널티: "적치량 손실 → 해당 Source 재충전"

### 3.1 요구사항
- 피격 시 CarryBin 적치량 일부 상실
- 상실량은 "추가 청소 필요량"으로 환원되어 **피격이 발생한 자리의 Source에 직접 반환**
- 단, **단계(Phase) 롤백 없이** "필요 수거량만" 증가

### 3.2 규칙
1. 피격 시 `loss`를 계산하고 `CarryBin.Load -= loss`
2. 피격을 유발한 Hazard가 속한 `SourceId`를 식별
3. 반환:
   - 반환 대상 Source가 `Depleted`가 아니라면:
     - `Remaining_CurrentPhase += loss`
   - 반환 대상 Source가 이미 `Depleted`라면:
     - 반환 무시(0 처리)
     - 이유: Depleted 부활 방지 + "단계 롤백 없음" 보장

> 요약: "Phase는 절대 뒤로 가지 않고, 현재 Phase의 남은 필요량만 늘어난다."

### 3.3 최소 피드백(UI)
- 피격 순간에 아래를 즉시 표시(텍스트만으로도 충분):
  - "Load -X"
  - "오염 +X"

## 4. 캠페인 루프(상위 흐름) — 구체화

### 4.1 캠페인 구조(권장 기본안)
- 총 스테이지 수: **6~7 스테이지 내외**
- 목표 템포: 스테이지당 **2~3분**(전환/결과 화면 포함 시 총 15~20분 가드레일)
- 캠페인 진행 흐름:
  1) Title / Start
  2) Stage 1 → 결과 화면 → Stage 2 → … → Stage N
  3) Ending(간단 연출 + 전체 요약)

### 4.2 스테이지 내 반복 루프(플레이어 관점)
- "수거 → (Capacity 도달) → Deposit으로 비우기 → 재진입"을 반복하며
  **모든 Source를 Depleted까지 밀어붙인다.**
- 스테이지의 기본 리듬:
  - 진입(수거 시작)
  - CarryBin 가득 차면 후퇴(Deposit)
  - 다시 진입(남은 Source 예산 처리)
  - 피격이 발생하면:
    - Load 손실 + 해당 Source 필요량 증가로 "추가 노동"이 생김
    - 따라서 "피격 최소화"가 곧 스테이지 완주 속도와 직결됨

### 4.3 스테이지 전환(결과/다음 진입)
- 스테이지 클리어 후 결과 화면(5~10초 목표, 스킵 가능):
  - Time
  - Hits(피격 횟수)
  - Deposits(비운 횟수)
  - (선택) Hazard 제거 횟수
- 결과 화면에서 다음 스테이지로 즉시 진행(로딩/연출 최소화)

### 4.4 난이도/변주 축(캠페인 진행에 따른 확장)
"깊이(Depth) 개념 없이"도 난이도 곡선을 만들 수 있도록, 아래 축을 사용한다.

- **Source 구성 변화**
  - Source 개수 증가(동시/순차 활성 중 선택)
  - Source 필드 형태(Circle/Rectangle) 조합
- **스폰 압력 변화**
  - 스폰 밀도(초당/면적당) 상승
  - 활성 탄 상한(가드) 조정
- **Hazard 압력 변화**
  - Hazard 비율 증가
  - Hazard 제거 룰의 요구 정확도 상승(타이밍/링 조건 강화 등)
- **운반 압력 변화**
  - CarryBin.Capacity 조정(작게 하면 Deposit 빈도 증가)
  - Deposit 위치/접근성 변화(동선 압박)
- **클리어 안정성 변화**
  - (선택) 잔탄 0 조건을 후반 스테이지에만 추가하여 "마무리 정리" 요구

## 5. 실패/재시도 정책(캠페인 완주 경험을 위한 최소 정의)

캠페인 "실패 없이 15~20분 완주"라는 목표를 위해, 실패 기준은 과도하게 무겁지 않게 설계한다.

- 기본 원칙:
  - 피격은 즉시 게임오버가 아니라 **진행 지연(Load 손실 + 필요량 증가)** 으로 작동한다.
- 스테이지 재시도(실패) 기준은 아래 중 하나를 채택(문서 외부에서 확정 필요):
  - 옵션 A: 제한 시간 초과 시 실패(스테이지 재시작)
  - 옵션 B: Hits 한도 초과 시 실패(스테이지 재시작)
  - 옵션 C: 실패 없음(대신 피격이 누적될수록 클리어 시간이 길어짐)

> 본 문서의 캠페인 템포 목표(15~20분)는 "옵션 C"에도 성립한다.
> 다만 "실패"의 의미를 명확히 하려면 옵션 A/B 중 하나를 후속 문서에서 확정하는 편이 좋다.

## 6. 데이터/콘텐츠 단위(캠페인 제작을 위한 최소 스펙)

### 6.1 CampaignDefinition(권장)
- Stage 리스트(순서 고정)
- 엔딩 조건(마지막 스테이지 클리어)

### 6.2 StageDefinition(권장)
- Deposit 설정(위치, 트리거 방식)
- CarryBin 설정(Capacity)
- Source 리스트
  - SourceId, 초기 Phase 예산(단계별 Remaining), 스폰 프로파일, 필드 형태/범위
- (선택) 스테이지 실패 조건(시간/히트/없음)
- (선택) 클리어 조건 옵션(잔탄 0 요구 여부)

## 7. 범위 밖(별도 문서)
- 튜토리얼/학습 스테이지 구성
- HUD/연출 상세(피격 피드백, Source 상태 표시 방식 등)
- Hazard 제거 룰의 세부 규칙 튜닝(타이밍, 링 폭, 보상/리스크)
- 메타 자원/정산(캠페인 외부 진행) 및 영구 성장
