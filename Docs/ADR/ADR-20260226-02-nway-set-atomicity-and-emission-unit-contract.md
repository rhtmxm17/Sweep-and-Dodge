# ADR-20260226-02-nway-set-atomicity-and-emission-unit-contract
> NWay 세트 원자성/시퀀스 보존과 밀도형·사건형 발행 단위를 분리한 결정

## 상태
- 반영됨

## 배경
- `LineEven + NWay` 조합에서 "한 샘플 지점에서 여러 방향이 동시에 나간다"는 사용자 의도와 "슬롯 분배" 구현 해석 사이에 의미 차이가 있었다.
- 예산/풀 부족 프레임에서 부분 소비가 발생하면 패턴 위상(`SpawnSequence`)이 흔들려 재현성과 체감 일관성이 떨어질 수 있다.
- 한편 밀도형 스폰(환경성 대량 생성)과 사건형 스폰(탄막 패턴)은 요청 단위를 동일하게 두면 운영 해석이 모호해진다.

## 결정
1. NWay 각도 규약 고정
- `NWay`/`RadialBurst` 슬롯은 360도 균등 분할을 기본 규약으로 사용한다.
- 계산식: `BaseAngleDeg + (360 / SlotCount) * slot`.

2. NWay 세트 원자성
- 원자성 단위는 "샘플 1지점의 NWay 1세트"로 고정한다.
- 세트를 프레임 내에 완결할 수 없으면 세트 전체를 다음 프레임으로 이월한다(부분 소비 금지).

3. 시퀀스 보존
- 원자성 이월 시 `SpawnSequence`는 증가시키지 않는다.
- 다음 프레임에서 동일 좌표/동일 슬롯 위상으로 재시도한다.

4. NWayCount 제약
- `NWayCount >= 2`를 필수 제약으로 고정한다(`CV023` Error).

5. 발행 단위 분리
- 밀도형 발행(`RateField` 중심): 요청은 엔티티 수 예약으로 해석한다.
- 사건형 발행(`EventBurst + Direction` 중심): 요청은 사건 단위 예약으로 해석한다.
  - ExecutionBegin에서 사건을 샘플/방향 슬롯으로 확장해 실제 엔티티를 소비한다.

## 대안
- 부분 소비 허용(가능한 만큼만 발사)
  - 장점: 예산 활용률이 높음
  - 단점: 패턴 위상 붕괴, 의도한 동시성 상실, 디버깅 난이도 증가
- NWayCount를 권장값으로만 유지
  - 장점: 작성 자유도
  - 단점: 콘텐츠 오류를 런타임 fallback에 의존하게 되어 의도-결과 불일치 증가

## 결과
- `LineEven + NWay` 시나리오에서 샘플 지점별 동시 다발 의도를 계약으로 명시할 수 있다.
- 예산/풀 경합 프레임에서도 패턴 위상 일관성과 재현성이 유지된다.
- 운영 관점에서 밀도형/사건형 스폰 해석 경계를 분리해 추후 확장(지속 사건 패턴) 논의를 단순화한다.
