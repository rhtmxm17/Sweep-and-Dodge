# ADR-20260219-06-cleaning-trail-request-owner-and-fast-sampling
> 청소 흔적 도입에서 Request 그룹 단일 writer, Top-K 샘플링, 원형 Source Valid 마스크를 채택한 결정이다.

## 배경
- 청소 흔적은 수거 이벤트와 스폰 좌표 선택을 연결해야 하므로, 데이터 소유권이 불명확하면 레이스/순서 문제가 생긴다.
- 목표는 대량 엔티티(최대 10만 탄환)에서 안정적인 프레임 유지이며, MVP 단계에서는 미세 정확도보다 처리량이 우선이다.
- 기존 스폰은 Source 내부 균일 샘플이라 같은 자리 고정 청소를 약화시키기 어렵다.

## 결정
- 오염도(CellPollution) writer를 `BulletRequestGroup`의 단일 시스템으로 고정한다.
  - 수거 시스템(`BulletVacuumRequestSystem`)은 셀 단위 Drop 요청만 누적한다.
  - 오염도 실제 갱신(regen/drop/clamp)은 `SourcePollutionUpdateSystem`이 단일 책임으로 수행한다.
- 스폰 샘플링은 MVP에서 `Top-K` 방식으로 고정한다.
  - K개 랜덤 후보 셀을 뽑아 가장 오염도가 높은 셀을 선택한 뒤, 셀 내부에서 지터 샘플한다.
- 원형 Source는 사각 격자 위에 `Valid 마스크`를 적용한다.
  - 셀 중심점 기반으로 valid를 bake하고, 스폰/드롭은 valid 셀만 사용한다.

## 대안 비교
### 대안 1: Vacuum 시스템이 오염도를 직접 갱신
- 장점: 시스템 수 감소
- 단점: 수거/오염 갱신 책임이 섞여 유지보수성과 순서 추적성이 떨어진다.

### 대안 2: 전체 룰렛(전 셀 누적 가중치) 샘플링
- 장점: 이론적으로 더 정확한 가중치 반영
- 단점: 셀 수 증가 시 비용이 높고 매 프레임 누적합 관리가 필요하다.

### 대안 3: 원형 Source 사각 근사 유지
- 장점: 구현 단순, 메모리 최소
- 단점: 원형 외곽에서 분포 오차가 커진다.

### 채택안 선택 이유
- 단일 writer 고정으로 소유권과 업데이트 순서를 명확히 유지할 수 있다.
- Top-K는 계산량이 작고 동선 유도 체감(고오염 우선)을 확보하기 쉽다.
- Valid 마스크는 기존 구조를 유지하면서 원형 외곽 오차를 크게 줄인다.

## 결과
- 청소 흔적 데이터 흐름이 `요청 생성 -> 단일 소비` 구조로 고정됐다.
- 스폰 좌표가 오염도 기반으로 편향되어 Source 내부 이동 유도가 가능해졌다.
- 원형 Source에서도 반경 외곽의 과도한 스폰/드롭을 억제할 수 있다.

## 리스크 및 후속
- 리스크:
  - 셀 중심점 기준 마스크라 경계 셀의 미세 오차는 남는다.
  - Top-K 값이 과도하면 특정 셀 집중이 강해질 수 있다.
- 후속:
  1. Playtest에서 2~5초 정지 시 밀도 하락 체감 여부를 수치/영상으로 검증
  2. Top-K, Drop/Regen 파라미터 스윕으로 고정 파라미터 범위 확정
  3. 경계 정확도 요구가 커질 경우 4샘플/커버리지 기반 mask로 확장 검토
