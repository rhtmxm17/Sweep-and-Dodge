## Session Goal
- 한 줄 목표: `몸체 + 표정 + 모션(FEEL)` 조합만으로 플레이어 또는 주요 Actor가 충분히 "캐릭터"처럼 읽히는지 프로토타입으로 검증한다.
- 완료 기준:
  - 검증 대상 Actor 1종에 대해 최소 표현 프로토타입 1개를 만든다.
  - 표정, 몸체 실루엣, FEEL 기반 반응 모션의 역할 분리를 명시한다.
  - 짧은 플레이 또는 캡처 기준으로 캐릭터성 판정 결과를 `pass / fail / inconclusive` 중 하나로 정리한다.
  - `pass`일 경우 후속 리소스 탐색 기준을 3~5개 항목으로 고정한다.
  - `fail` 또는 `inconclusive`일 경우 부족 축과 다음 보강 실험 항목을 남긴다.
- 이번 세션에서 하지 않을 것:
  - 최종 챕터 콘텐츠 확정
  - 대규모 아트 리소스 구매 또는 일괄 수집
  - 장기 Animator 상태 머신 설계 확정
  - DOTS 런타임 구조 변경

## Inherited Context
- 현재 방향성은 리소스를 다시 탐색하기 전에, `몸체 + 표정 + 모션(FEEL)`만으로도 캐릭터성이 성립하는지를 먼저 검증하는 것이다.
- `FEEL`은 Hazard Bullet 피격 피드백 등 반응성 높은 프레젠테이션 레이어에도 사용할 계획이 있으므로, Actor의 짧은 반응 모션과 통일된 도구 체계로 다룰 수 있다는 전제가 있다.
- 이번 검증이 통과하면 이를 전제로 챕터 구조 고정 작업과 리소스 재탐색 범위를 좁힌다.

## Now
- [ ] T1. 표현 전략 프로토타입의 검증 축과 합격 기준을 세션 초반에 고정한다.
  - 목적: "캐릭터처럼 보인다"를 감각 표현이 아니라 반복 가능한 판정 기준으로 바꾼다.
  - 완료 기준:
    - 최소 3개 이상의 판정 축을 확정한다.
    - `pass / fail / inconclusive` 조건을 세션 내에서 단일 해석 가능하게 적는다.
  - 검증:
    - TaskBoard 또는 연결 문서에 기준이 문장으로 남아 있다.
  - 근거:
    - 리소스 재탐색 전에 표현 전략의 성립 여부를 먼저 검증해야 한다는 현재 합의.

## Next
- [ ] T2. 검증 대상 Actor 1종과 최소 구성 요소를 선택한다.
  - 완료 기준:
    - 대상 Actor 1종
    - 몸체 형태 1안
    - 표정 세트 최소 2~3종
    - FEEL 반응 모션 최소 3종
  - 검증:
    - 대상과 구성 요소가 세션 문서 또는 구현 계획에 명시된다.
  - 근거:
    - 이번 세션은 표현 전략의 가능성 테스트가 목적이며, 범위를 1종 Actor로 제한해야 판단이 선명해진다.
- [ ] T3. 최소 프로토타입을 제작하고 캡처 또는 짧은 플레이 기준으로 읽힘을 점검한다.
  - 완료 기준:
    - 정지 상태, 반응 상태, 전환 순간을 확인 가능한 결과물이 있다.
    - 몸체/표정/모션 중 무엇이 캐릭터성을 만들었는지 관찰 메모가 남아 있다.
  - 검증:
    - 캡처, 영상, 플레이 관찰 메모 중 최소 1개가 남아 있다.
  - 근거:
    - 캐릭터성은 정적 스펙보다 실제 반응 장면에서 판정해야 한다.
- [ ] T4. 검증 결과를 바탕으로 챕터 구조 고정 전제와 리소스 탐색 기준을 정리한다.
  - 완료 기준:
    - `pass`면 유지할 표현 축과 필요한 자산 범주를 적는다.
    - `fail` 또는 `inconclusive`면 보강이 필요한 표현 축과 재실험 방향을 적는다.
  - 검증:
    - 다음 세션이 바로 시작 가능한 판단 메모가 남아 있다.
  - 근거:
    - 이번 세션 결과는 후속 챕터 구조 고정과 리소스 탐색의 필터 역할을 해야 한다.
