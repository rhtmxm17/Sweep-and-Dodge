# AGENTS.md (Docs/TechnicalDesign)

## Document Role
- Documents in this folder describe **technical design intent, assumptions, and plans**.
- They are **NOT decisions** and **NOT binding rules**.

## Usage Rules
- Use these documents as reference before implementation.
- Do NOT treat contents as finalized architecture.
- ADR is for important decisions and rationale, not every implementation update.
- Create ADRs for high-impact architecture choices, ownership/order rules, and decisions requiring trade-off records.
- Keep formatting constraints minimal.
- Mandatory: file name format and `## Metadata`.
- Suggested (session-level): section order, heading style, and template structure.

## Editing Rules
- Updating these documents does NOT imply a technical decision.
- If implementation diverges, update this document first.
- Add or update an ADR only when the divergence creates an important decision worth preserving.
